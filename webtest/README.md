# TensorFlow.js CDN 入门示例

双击 `index.html`，用浏览器打开即可；无需 npm、构建工具或后端服务。首次加载需要联网访问 jsDelivr。

## 引入方式

```html
<script src="https://cdn.jsdelivr.net/npm/@tensorflow/tfjs"></script>
<script src="app.js"></script>
```

`src` 内直接填写 URL，不要放入 Markdown 的 `[文字](网址)` 格式。库脚本加载后提供全局 `tf`，因此业务脚本要放在后面。本例按请求使用不带版本号的地址；需要长期复现时，可以改成经过验证的固定版本地址。

## 操作步骤

1. 等待页面显示库版本及计算后端。
2. 点击“运行张量示例”：查看向量逐项相加 `[11,22,33]` 和矩阵乘法 `[[50],[110]]`。
3. 点击“开始训练”：用 5 个样本学习 `y = 2x + 1`，观察 100 轮训练中 loss 的变化。
4. 输入 x 并预测，例如输入 3，预测值应接近 7。页面同时显示公式参考值及误差。

训练数据的 x 范围是 [-1, 1]。这个例子使用线性数据与线性模型，便于理解；实际任务不能据此假设模型在训练范围外仍能准确预测。

## 文件与 API

- `index.html`：CDN 引入、操作界面、简短代码片段。
- `app.js`：完整实现及中文注释，包括初始化失败提示、输入校验与张量释放。
- `benchmark.js`：TF.js CPU / WebGL 容量与性能测试。
- `tf.tensor1d / tf.tensor2d`：创建一维或二维张量。
- `add / matMul`：逐项加法与矩阵乘法。
- `tf.sequential / tf.layers.dense`：创建一个单神经元线性模型。
- `compile / fit / predict`：配置优化器与损失、训练、预测。
- `tf.tidy / dispose`：释放张量，避免重复操作导致内存累积。异步训练通过 `finally` 手动释放数据。

模型只存在当前页面内存中，刷新后需要重新训练。无法加载时，请检查 CDN 网络访问和浏览器控制台。

## 内存、显存与算力测试

页面顶部提供独立测试面板，选择 CPU 或 WebGL 后分别运行：

- **容量**：默认持续探测，不设软件容量上限，每次增加 8 MiB，直到分配/校验失败或用户停止。也可以选择固定上限或填写自定义正整数 MiB，允许超过 1024 MiB。每块创建独立 float32 张量并运算、校验，持续保留此前的块；固定上限完成后再次校验全部块。结果是本次成功分配的逻辑张量字节下限，不是物理总容量、剩余容量或模型可用容量。WebGL 的纹理布局、精度和驱动缓存会影响实际占用；集成显卡或软件渲染也可能提供 WebGL。
- **速度与算力**：矩阵边长可选 128、256、512，预热 2 次后测量 7 次，报告中位数。`await output.data()` 确保完成计算及回读；GFLOP/s 按 `2 × N³ / 秒 / 10⁹` 估算，不是硬件峰值，也不能直接换算成模型 tokens/s。该 CPU 后端为普通 JavaScript，未使用 WASM。
- **数据往返**：4 MiB 输入经过加法后回读 4 MiB 输出，预热 1 次、正式测量 5 次。以输入加输出共 8 MiB 计算有效吞吐；包含张量创建和计算，不是纯显存/PCIe 带宽。CPU 后端没有 GPU 传输。
- **资源信息**：展示浏览器允许提供的设备内存粗略档位、JS 堆统计、逻辑处理器数量和 `tf.memory()` 活跃张量统计。缺少字段时显示“未提供”；GPU 活跃字节不是总显存。JS 堆也不是页面总内存。

测试期间禁用其他计算，结束后恢复原后端并释放测试张量，日志显示测试前后的活跃张量数。停止按钮在当前计算结束后生效；同步 CPU 计算或驱动卡顿期间不能立即中止。部分结果与失败均单独标记。持续探测可能耗尽资源并导致浏览器关闭页面，无法保证捕获所有内存不足错误。每块校验后尝试将最近成功容量保存到本机 localStorage，重新打开相同地址可查看；异常中断记录不会被标作硬件极限。浏览器禁用存储时页面会说明记录无法保存。TF.js 的后端缓存可能在释放张量后仍保留，刷新页面可重置。

## 纯文字报告

每次容量或性能测试完成、停止或捕获错误后，页面自动生成纯文字报告，按顺序汇总本次页面会话的测试。先分别运行 CPU / WebGL 容量与性能测试，最后点击“下载纯文字报告（.txt）”即可导出汇总，也可以直接复制报告文本。

报告明确说明这是浏览器中的 TensorFlow.js 测试，包含时间、浏览器标识、TF.js 版本、测试后端及配置、已验证容量、速度与算力、结束原因、资源快照和指标解释。未执行的测试不会生成虚构数据；历史容量记录不混入当前报告。页面被系统直接关闭时无法生成最终报告，只有此前成功保存的容量进度可能恢复。

对比时保持相同浏览器、矩阵大小和前台状态；后台节流、温度、其他应用负载及首次编译都会影响结果。

## 验证脚本

`tests/benchmark.cjs` 使用真实 TF.js CPU 后端和简单 DOM 替身，验证容量重复运行、矩阵及数据往返校验、持续探测的取消/失败、进度恢复、报告、WebGL 不可用、CDN 缺失和张量释放。超过 1024 MiB 的控制流程使用缩小后的分配验证，不代表硬件大容量实测。传入从上述 CDN 获取的本地库文件即可运行（保存为 `.cjs`，使用 Node.js）：

```powershell
node tests/benchmark.cjs C:\path\to\tf.min.cjs
```

此脚本不验证浏览器布局或 GPU 性能，WebGL 需在目标浏览器中手动运行测试。
